# Agent 架构设计

本文件描述项目中的主要模块、接口契约与扩展点，供实现与评审参考。

## 模块划分
- `Perception`：输入适配器，负责将外部输入（HTTP、CLI、消息队列、语音、图像）转换为内部事件结构。
- `Memory`：短期/长期记忆层，短期保存在会话内，长期使用向量数据库或KV存储检索。
- `Planner`：核心决策引擎，将高层目标分解为有序步骤（子任务）。
- `Executor`：执行器，负责调用工具/外部API，管理重试与补偿逻辑。
- `Tools`：外部服务适配器（搜索、数据库、操作执行器等），实现统一接口以便替换与mock。
- `Safety`：输入/输出过滤、策略检查、权限校验、审计日志。
- `Observability`：日志、指标、追踪与报警。

## 接口契约
- 所有模块使用 JSON-like 字典传输事件，包含 `request_id`、`timestamp`、`user_id`（可选）、`payload`。
- 错误使用统一错误码与可重试标记，Executor 按策略重试或发出补偿事务。

## 扩展点
- 插件化 Planner（策略模式）以支持多模型/规则引擎。
- Memory 抽象以支持向量检索或关系型存储。

## 性能与可用性考虑
- 关键路径要支持异步执行与限流。
- 将长时间运行任务交由任务队列（如 Celery/RQ/Kafka）异步处理。
