# OpenAI-Compatible LLM Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one generic OpenAI-compatible backend that can call Qwen, DashScope, or any other provider implementing the OpenAI Chat Completions contract.

**Architecture:** Reuse `OpenAICompatibleAdapter` for every compatible provider. Expose only `AGENT_LLM_BACKEND=openai-compatible` with explicit API key, base URL, and model variables; keep Gemini's native adapter and OpenAI's existing backend behavior unchanged.

**Tech Stack:** Python 3.11+, OpenAI Python SDK 1.58.1, pytest, Docker Compose.

## Global Constraints

- `AGENT_LLM_BACKEND=openai-compatible` is the only compatible-provider backend value.
- `OPENAI_COMPATIBLE_API_KEY`, `OPENAI_COMPATIBLE_BASE_URL`, and `OPENAI_COMPATIBLE_MODEL` are required when that backend is selected.
- API keys must never be logged or returned.
- Compatible requests disable SDK retries with `max_retries=0`.
- No embeddings, native DashScope SDK, streaming, tool calls, web search, thinking mode, or multimodal inputs.

## Files

- `src/agent/infrastructure/llm/llm_compatible.py`: shared adapter and validation.
- `src/agent/infrastructure/llm/llm_factory.py`: generic backend selection.
- `src/agent/config.py`: generic environment variables.
- `tests/test_llm_compatible.py`, `tests/test_gemini_factory.py`: adapter and factory coverage.
- `docker-compose.yml`, `tests/test_deployment_config.py`, `README.md`: runtime forwarding and documentation.
