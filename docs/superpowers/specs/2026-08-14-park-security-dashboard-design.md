# Park Security Mock Dashboard Design

## Goal

提供一个无需前端构建链的静态演示页，直观展示 `park-security` 当前模拟数据能提供的安防态势、事件详情、证据链和值班升级能力，并演示受审批保护的事件处置流程。

## Scope

页面只使用当前仓库内确定性的 `park-1` 模拟数据，不连接数据库、不调用 MCP 网络接口、不读取真实凭证。页面中的确认事件、创建工单和关闭事件仅修改浏览器内存状态，刷新页面后恢复初始数据。

当前覆盖三个场景：

- 夜间实验区异常门禁
- 园区入口访问失败与徘徊
- 机房消防与通风设备故障

## Delivery and Runtime

新增 `demos/park-security/index.html`，页面所需样式和脚本内置在文件中，不引入 React、Vue、npm 或新的运行时依赖。

在仓库根目录运行 `python -m http.server 8088 --directory demos` 后，通过 `http://127.0.0.1:8088/park-security/` 访问。

## Page Layout

- 顶部栏：园区名称、`MOCK DATA` 标识、模拟时间和数据更新时间。
- KPI 区：事件总数、严重/高风险事件、原始告警数、有效告警率。
- 事件区：事件列表、风险/状态筛选和选中态。
- 详情区：场景、风险等级、状态、影响范围、责任团队和建议处置方案。
- 证据区：按时间排序的门禁、视频、巡更、消防、设备和值班证据时间线。
- 值班区：值班人员、值班时段、负责区域和两级升级规则。
- 处置区：确认事件、创建工单、关闭事件按钮及当前处置状态。

页面采用深色园区运营看板风格，同时保证窄屏下可以纵向浏览；按钮、筛选器和事件卡片使用语义化 HTML 控件。

## Data Model and State

JavaScript 内置与 `MockSecurityRepository` 对齐的事件、证据、值班上下文和工单初始数据。页面状态包括：

- 当前选中的 `event_id`
- 当前风险和状态筛选
- 事件状态、确认时间、工单和审计记录
- 当前模拟查询时间

渲染逻辑从状态生成 KPI、事件卡片、详情和时间线；不通过字符串拼接执行 HTML，用户可控字段统一使用文本节点或安全转义。

## Interaction Rules

- 默认选择 `event-fire-003`，突出当前最高风险事件。
- 点击事件卡片切换详情；筛选结果为空时显示明确的空状态。
- 只有 `open` 事件可确认；只有 `confirmed` 事件可创建工单；只有 `work_order_created` 事件可关闭。
- 处置动作弹出二次确认，并要求填写操作员和说明；成功后更新状态、时间线和审计记录。
- 页面明确标注处置操作是“模拟操作”，不代表真实工单系统已写入。

## Error and Safety Behavior

- 不提供真实审批凭证输入或持久化能力。
- 非法状态转换显示可理解的提示，不改变事件状态。
- 未知事件、空筛选结果和未知区域显示空态或错误提示，不抛出未处理异常。
- 页面不展示真实视频、人脸或人员敏感数据；证据引用仅作为演示文本。

## Verification

- 用 Python 静态服务器打开页面，确认无控制台初始化错误。
- 验证三个事件可以切换，风险/状态筛选结果正确。
- 验证值班上下文和证据时间线与当前 mock fixture 一致。
- 验证处置流程只能按 `open -> confirmed -> work_order_created -> closed` 顺序执行，刷新后状态恢复初始值。
- 对内置 JavaScript 运行语法检查，并执行仓库现有安防测试。
